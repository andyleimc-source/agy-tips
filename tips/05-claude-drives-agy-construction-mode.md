# 05 · 施工模式：Claude Code 写卡 + agy 施工 + Claude 验收

**问题**：Claude Code 直接写实现是 token 大户，一个中等功能几万 token 起步。而 agy 走 OAuth 吃 Google AI Pro/Ultra **订阅额度**，写代码这件事对它是"包月不额外计费"的。

**做法**：把角色拆开——

| 谁 | 干什么 |
|---|---|
| Claude（司机） | 写任务卡、审 diff、跑验证、合并、写返工要求 |
| agy（施工） | 严格照卡实现 + 自检 + commit |

Claude 自己上手的只剩：几行小修、架构判断、tricky 逻辑、写卡本身、验收。

起子脚本：[`scripts/agy-do`](../scripts/agy-do)，用法 `agy-do <任务卡文件> [--async] [--here]`。

## 跑了一阵之后暴露的两个问题

**问题不在 agy 偷懒，在司机没规矩。**

1. **司机根本不派。** 只要「施工模式」是靠口令触发的，Claude 默认还是自己写；而「小修/tricky 逻辑自己上」这个例外口子一宽，它随手就把活划进去了。
   → 做成一个**显式技能**（slash command / skill），叫才进、不叫不进，别指望它自觉。
2. **卡太薄 → agy 敷衍 → 验收还查不出来。** 薄卡等于让 agy 自由发挥；而司机验收时只读 agy 那段自我总结，糊弄自然查不出来。
   → 加两道闸：**发卡前的卡质量闸** + **验收时的机器判定清单**（下面两节）。

## 发卡前的闸（任一条不过就回去补）

1. 「改哪些文件」是**具体路径清单**，不是「相关文件」
2. 「怎么验收」每条都是**能复制去跑的命令 + 期望输出**，不许出现「确认功能正常」这种没法执行的话
3. 卡里所有「现在的行为是 X」「这个只被 Y 用」，司机**自己先 grep 验过**——你写错了 agy 会照错的干
4. 验收命令先在**当前代码**上跑一次记下基线——没基线就分不清 agy 改完是真绿还是本来就绿
5. 通读一遍：信息够不够**一个没看过这个项目的人**照着干完？不够就是薄卡

## 验收的机器判定（先跑这些，再人肉审 diff）

设 `RANGE` = `<base>...HEAD`（worktree 模式）。

| 查什么 | 怎么查 |
|---|---|
| 有没有回执 | `grep -A20 '## agy 回执' <卡>` |
| 改的文件越没越界 | `git diff --name-only $RANGE` 对卡里的白名单 |
| 混进流水文档没 | 上一步清单里有 plan/progress/handoff → 剥离 |
| 断言归零是不是改名糊弄 | `git diff $RANGE \| grep -E '^[-+].*<那个符号>'`：只有 `-` 才算真删；出现 `+` 带相似新名 = 糊弄 |
| 卡里每条验收命令 | 在 worktree 里自己跑一遍，跟基线比 |

人肉审 diff 时重点三处：**卡里的前提 agy 有没有复核**、**有没有偷懒实现**（空实现、`TODO`、`catch {}` 吞异常、把测试改宽松而不是把代码改对）、**有没有顺手改无关的东西**。

**返工最多两轮。** 第三轮还不过，要么卡的问题、要么这活 agy 啃不动，司机自己接手——反复喂同一张卡比自己写更贵。

## 异步：别让施工卡住司机的会话

前台跑法下，`agy-do` 一跑，司机就在那干等半小时，期间接不了别的话。

`--async` 把施工丢到后台，日志落 `~/.agy-runs/<项目名>--<slug>/out.log`（目录带项目名前缀，不同项目的同名卡不互相覆盖；同名卡在跑时再起一次会被拒绝），**结束时写一个 `exit` 文件（内容 = 退出码）作为唯一完成信号**。司机挂一句看门狗就能被自动叫醒：

```bash
until [ -f ~/.agy-runs/<项目名>--<slug>/exit ]; do sleep 20; done
echo "干完了 rc=$(cat ~/.agy-runs/<项目名>--<slug>/exit)"
```

两个设计点：

- **盯「文件出现」而不是盯日志关键字。** 文件要么在要么不在，不会读到写了一半的半截状态。
- **`exit` 由外层壳写，不是 agy 自己写。** agy 说「我干完了」不可信（偷懒时也这么说），但壳能区分正常结束 / 报错退出 / 超时被掐——三种情况都会落 `exit`，数字不同。所以 agy 中途崩了司机也不会傻等。

因为地点固定、跟谁起的无关，**另开一个窗口人工跑的 `agy-do --async`，司机一样感知得到**，不需要谁通知谁。
[`scripts/agy-runs`](../scripts/agy-runs) 列出所有后台施工（在跑 / 待验收 / 失败），并从日志里捞出最该盯的三个信号：有回执、零 commit、逃逸警报。

## 四个真踩过坑才有的设计

**1. worktree 隔离 + 逃逸检测。** agy 有把 worktree 里的 `.git` 指针文件解析回主仓、直接往主分支提交的前科。脚本在施工前后各拍一次快照（主分支 HEAD + 主仓脏文件列表），事后比对报警。**只报警不自动回滚**——并行会话可能同时在推进主分支，自动 revert 比逃逸本身更危险。

**2. 开工前把工作目录写进 `trustedWorkspaces`。** agy 的信任是精确路径匹配、不认父目录前缀，所以主仓被信任不代表新建的 worktree 被信任。未信任的目录在 print 模式下弹不出信任框 → 秒超时零输出，很容易被误判成 OAuth 失效（详见 [04](04-worktree-untrusted-folder-print-timeout.md)）。`--dangerously-skip-permissions` 只跳工具权限，不跳文件夹信任。

**3. `--here` 逃生口。** Tauri / Xcode / 大 node_modules 这类项目，新建 worktree 意味着重新装依赖、重新全量编译，比省下来的 token 更亏。`--here` 原地干，代价是没有隔离，所以脚本强制要求开工时工作区干净——否则事后分不清哪些改动是 agy 写的。

**4. 参数顺序：`--print-timeout` 必须放在 `-p` 前面。** `-p/--print` 会把紧跟其后的 token 当成 prompt 值吃掉。

## 施工指令里值得写死的几条

- **工作区钉死**：写清唯一允许读写的绝对路径，要求开工先 `pwd` 自证，发现自己在工作区外就零写操作、写回执后停。
- **卡里的前提自己复核**：卡写「这个函数只被 X 调用」，agy 不会去 grep 验证，照卡删就可能打断活路径。要求它施工前自己核一遍。
- **断言归零靠删除，不许靠改名**：验收条件写成"grep 某符号零命中"时，agy 会把活生产函数改个名来让它归零。
- **有歧义写回执别猜**：约定在任务卡末尾追加 `## agy 回执`，脚本事后 grep 这个标题提醒司机。
- **禁区文件清单**：progress / plan / decision / handoff 这类流水文档一律别碰，否则会被顺手写进施工 commit。

## commit 署名

用 `GIT_AUTHOR_NAME=agy GIT_AUTHOR_EMAIL=agy@antigravity` 硬标记，别指望它记得自己署名。之后 `git log --author=agy` 一查就知道哪些代码是施工方写的、该重点审哪些。
