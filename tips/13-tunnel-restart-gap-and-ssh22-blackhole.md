# 13 · 隧道断过一次,任务就跟着挂:重启真空期 + 22 端口偶发黑洞

tips/06 讲了给 agy 单开一条专用出口隧道,tips/08 讲了 ASN 归属的坑。这篇是隧道**稳定性**本身踩的坑——通道本身好好的,但断线重连的那几秒,恰好撞上任务正在跑,任务就直接被打断,只报一句没有信息量的 `Agent execution terminated due to error`。

## 复现

一次 agy 任务中途报错终止。翻 `~/.gemini/antigravity-cli/log/cli-*.log`(agy 默认就在写这个日志,不用额外开 `--log-file`),看到:

```
proxyconnect tcp: dial tcp 127.0.0.1:7899: connect: connection refused
```

对照 `agy-tunnel` 的健康检查日志,发现同一秒健康检查刚好判定失败、`pkill` 掉了 ssh 隧道进程。

## 根因 1:健康检查一次抖动就杀,杀完到重启之间是真空期

`agy-tunnel healthcheck` 原来的逻辑是:探测一次失败就 `pkill`,交给 launchd 的 `KeepAlive` 重新拉起。问题是:

- `ssh -N -D` 的本地 SOCKS5 监听端口,要等 SSH 握手 + 认证**全部完成**才会 `bind`,不是进程一启动就有——这意味着从 kill 到端口重新可用,中间必然有一段真空期(握手耗时 + launchd 的 `ThrottleInterval`)。
- agy 自己的重试预算很短(实测 2 次重试,退避约 1~1.5 秒,总共 2.5 秒左右就放弃),真空期只要超过这个数,任务必挂。
- 而健康检查的判定本身可能是一次性网络抖动,压根不代表隧道真的坏了——**误杀比隧道本身的问题更伤**。

**改法**:健康检查改成「连续两次都失败才 kill」,单次抖动不触发重启,减少了绝大多数的误杀。

## 根因 2:只走 22 端口,遇到针对性封锁就彻底连不上

如果你在国内网络下用境外服务器做隧道,SSH 走的 22 端口有可能被临时针对性限流/黑洞(不是永久封,是间歇性的,持续几分钟到十几分钟不等)。这段时间里健康检查怎么重启都没用,因为压根连不上服务器。

**改法**:服务器 sshd 额外开一个 443 端口监听(**保留 22,别关**,配置错了容易把自己锁在外面),`agy-tunnel up()` 每次启动先探测 443 通不通,通就走 443,不通退回 22。两条腿走路,不把命运押在一个端口上。

## 走过的弯路:想用 gost 彻底消灭真空期,但踩了兼容性 bug

理论上更彻底的方案是:本地用一个常驻监听的转发工具(比如 [gost](https://github.com/go-gost/gost))接力 SSH 上游连接——工具本身**永不退出**,上游连接断了它自己后台重连,本地端口一秒都不消失,agy 那 2.5 秒的重试预算就够用了。

实测下来:gost 3.x 的 `forward+ssh://` 链路,SSH 认证能过,但请求 `direct-tcpip` 转发(SOCKS5 的核心机制)时被服务器拒绝:

```
ssh: rejected: connect failed (open failed)
```

服务器侧抓包确认,压根没有对目标地址发出过 TCP 连接尝试——说明请求在到达"真正去连目标"这一步之前就被拒了,不是网络问题,是协议层不兼容。GitHub 上有独立的同类报告([go-gost/gost#257](https://github.com/go-gost/gost/issues/257)),看起来不是我这台服务器特有的问题。没深挖到底是哪个版本的哪个行为差异,直接弃用,回退到轻改现有 `ssh -D` 方案。

如果你也想走这条路,**先用几个真实请求验证 `forward+ssh` 能不能实际转发数据成功**,别直接换到生产环境——症状很隐蔽,SOCKS5 握手和 SSH 认证都会显示成功,只有实际转发时才报错。

## 结论

- 断线重连的隧道,健康检查別「一次失败就杀」——要杀之前先确认不是抖动,不然自己制造的真空期比隧道本身的问题还频繁。
- 只用一个端口连服务器是单点风险,尤其在会被针对性限流的网络环境下,给 sshd 多开一个端口做备份,成本很低。
- gost 之类的"接力工具"理论上更优雅,但引入新工具就是引入新的兼容性风险——先小范围验证真实转发,再决定要不要换。

## 涉及脚本改动

`scripts/agy-tunnel` 加了 `healthcheck` 连续两次失败才 kill 的计数逻辑(状态文件在 `$TMPDIR/agy-tunnel-failcount`),`up()` 加了 443/22 自动探测切换。
