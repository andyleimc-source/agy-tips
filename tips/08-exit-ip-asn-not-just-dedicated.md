# 08 · 专用出口 IP 也不一定稳:Google 判的是 ASN 归属,不是「独不独占」

tips/06 讲了给 agy 单开一条专用出口线路的做法。这篇是后续踩坑:**专用、固定的 IP 不等于稳定**,还得看这个 IP 的 ASN(网络归属)信息。

## 复现

按 tips/06 的方案,把出口换成一台海外 VPS(物理机房在美国硅谷)之后,`FAILED_PRECONDITION: User location is not supported for the API use` 大幅减少,但没有归零——还是会间歇性出现,只是频率低了很多。

## 排查

用 `curl --socks5-hostname` 走这条隧道查 `https://ipinfo.io`,IP 归属地理位置显示确实是美国。但 ASN(自治系统号)一栏,注册主体是国内的云服务商。也就是说:**Google 判断"这个请求算哪个地区"时,参考的不只是 IP 的地理坐标,还有这个 IP 段背后注册机构的归属**。同一个物理机房、同一个 IP,地理位置库判它在美国,ASN 归属库判它跟另一个地区更近,两边打架,结果就是间歇性。

## 又试了一次:换成 Cloudflare WARP

猜测"只要是西方主流网络的 ASN 应该就稳",于是用 Cloudflare WARP(`warp-cli` 开代理模式)把出口再换一次——ASN 是 Cloudflare 自己的(AS13335),不存在归属地含糊的问题。

结果**更差**:同样的测试脚本,被拒的比例比换 WARP 之前还高。说明"只要不是特定地区的 ASN 就行"这个猜测也不对,Google 对 WARP 这类知名代理/VPN 出口本来就有额外的风控,和"地区判定"是两件事叠在一起。

## 真正稳定的方案

换成目标云厂商在目标区域**自己的 IP 段**——如果调用的是 Google 自家的 API,就用 Google Cloud(GCP)自己的虚拟机做出口。同一套 tips/06 的隧道架子不用动,只是把服务器换成 GCP 的机型:

- 区域选 API 服务器就近的美区(如 `us-west1`),免费额度覆盖的 `e2-micro` 机型即可,不需要大配置
- ⚠ 2024 年后 GCP 对**任何**外网固定 IPv4 都要收费(约 $3.65/月,不在免费额度内),免费额度只覆盖机时,别被"e2-micro 免费"的说法误导,实际约 $4-5/月
- 换上之后同样用 `agy -p "在线"` 之类的探活请求测几十次,归零

## 结论

排查这类"间歇性地区判定"问题时,别止步于"IP 是不是独占的",要往下一层看 ASN 归属;而且不是随便一个"看起来正规"的西方 ASN 就行,最稳的是目标服务本身所在云厂商的自留 IP 段。

## 涉及脚本改动

`scripts/agy-tunnel` 支持了 `AGY_TUNNEL_IDENTITY` 环境变量,用来指定连接新服务器要用哪把 SSH 私钥(GCP 等云厂商常用专门生成的 key,不一定是默认的 `~/.ssh/id_ed25519`)。

`scripts/agy-do`(施工模式驱动脚本)加了自动重试:探测到日志里出现地区判定错误、且这一轮 HEAD 没动、工作区也干净(零产出)时,自动重跑同一张任务卡,最多 3 次,退避 30s/60s。只在零产出时重试,避免在半成品上再跑一遍。
